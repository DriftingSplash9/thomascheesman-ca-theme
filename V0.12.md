+ pages via the WP REST API and HEAD-tests every image in each

returned **0 broken**. No theme code changed.

### 2. Hostinger "Coming Soon" mode — found ON, turned OFF

The staging site was serving a Hostinger "Coming Soon" placeholder to
logged-out visitors (admins + REST bypassed it). Thomas disabled it.
⚠️ Confirm it stays off at go-live.

`themes/astra/style.css` was 404ing — Astra was **double-nested**

showed duplicate "TC 'ventures Child" rows under "Broken Themes";
clicking **Delete** on one **deleted the active child theme directory**
from the server. Recovery: pushed a commit to `main`, which triggered
Hostinger's GitHub auto-deploy and rebuilt the theme folder. Then fixed
Astra properly: deleted the broken nested `astra` folder via File
Manager, reinstalled **Astra 4.13.2** fresh (Installed, NOT Activated).
Verified `astra/style.css` → 200, "Broken Themes" gone.

### 4. `.gitignore` — dev helpers ignored (commit `419e26c`)

Added `db-image-audit.py`, `build-image-audit.py`, `test-image-urls.py`,
`remove-dead-images.py`, `image-audit*.xlsx` to `.gitignore`.

### 5. Page-by-page once-over + fixes (commit `52659df`, theme → 1.0.294)

Drove a browser through all 15 live pages. **Result: every page
renders, every site asset returned 200 — zero broken images, zero

## Known sharp edges

**New / open this session:**

1. **Gallery "black box until hover" — partially mitigated, verify.**
   On the kid photo galleries, some lazy-loaded masonry images stay
   blank (showing the `#1a1410` item background) until hovered, then
   paint instantly. Root cause: a Chrome paint-invalidation quirk with
   `loading="lazy"` images inside a CSS multi-column (`column-count`)
   masonry. This session removed `decoding="async"` as the safe first
   fix. **Thomas should verify in his own browser whether it still
   happens.** If it does, the real fix is reworking the gallery away
   from CSS columns (`.tc-photo-gallery__grid` in `style.css`) — do
   that as a focused task with before/after testing, not blind.
2. **Never click "Delete" in the WP admin Themes page** — when the
   parent theme is unresolvable, a "Broken Themes" row's Delete button
   removes the **active theme's directory**. Recovery is a push to
   `main` (triggers the Hostinger redeploy).
3. **Kid-spoke pages have a scroll-jacking hero.** Synthetic
   mouse-wheel could not advance past the name hero in the automated
   browser (keyboard + scrollbar worked). Likely just a tooling
   artifact — Thomas was asked to confirm with a real wheel and said
   "good to go."
4. The 5 old-site posts are **Drafts, not deleted** — recoverable.

**Carried from V0.11 (still true):**

5. **Video playback cannot be verified in an automated browser** —
   verify videos by byte inspection or Thomas's own browser.
6. Crest video files are large (~62 MB) — optional future re-encode.
7. /contact email obfuscation is rot13 + JS-decode only.
8. Leaderboards are open-write (acceptable per Thomas).
9. Photo-gallery counts in `inc/desk-menu.php` are hardcoded.

**Resolved:** V0.11 #3 (Astra "503" — was the double-nested folder),
