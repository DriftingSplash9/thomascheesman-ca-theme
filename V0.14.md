## The bug hunt (because it's instructive)

We chased the "abilities don't register" bug through ~5 false fixes before finding the real cause. For the next agent registering more abilities:

- **`wp_register_ability()` returns `null` silently on every failure path**. No exception, no WP_Error, just NULL. Easy to miss.
- The only way to find out WHY a registration fails is `_doing_it_wrong()` notices (with `WP_DEBUG` on) OR capture via the `doing_it_wrong_run` action filter.
- **Abilities register on `wp_abilities_api_init`** — different hook from categories.
- **Categories register on `wp_abilities_api_categories_init`** — fires BEFORE the abilities hook. They are TWO hooks.
- Abilities that reference an unregistered category fail silently.
- Closures in callbacks are fine (per the official docstring example). String / array callables also fine.
- The diagnostic infrastructure we built to find this was stripped in `2fa64e2`. If you need it again, the patterns are in V0.14 of `inc/agent-abilities.php`'s git history.
