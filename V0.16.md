## Engine architecture — full action verb surface

Built up across V0.15 → V0.16. The complete set:

### Core state verbs (V0.15)
- `reveal: [ids]` — set state to "shown"
- `hide: [ids]` — set state to "hidden"
- `remove: [ids]` — set state to "gone"
- `surface: <id>` — swap the drawer background
- `flag: <name>` — set a progress flag in `W.flags`
- `clue: <text>` — show the aged-paper clue card
- `effect: <name>` — play a named effect (`flash` and `blackhole`)
- `notify: <event>` — POST to drawer-events.php → email Thomas

### Added in Phase 4 (V0.16)
- `video: <object-id>` — play a WP video attachment
- `fullscreen: <object-id>` — element.requestFullscreen()
- `passcode: { expected, success, failure }` — number-pad modal
- `hangman: true` — Hangman mini-game
- `choice: { prompt, options:[{label, do}] }` — branching decision modal
- `youtube: <id|url>` — YouTube iframe overlay
- `stream: { url, label }` — HLS / direct-mp3 audio with corner player widget
- `pacman: true` — full Pac-Man modal using desk-games.js's game loop
- `bubbles: true | { count }` — animated bubble particle effect
- `crash: <object-id>` — full-viewport drop + screen-shatter gag
- `link: <url>` — open https URL in a new tab

### New interaction-level fields (V0.16)
- `require: { all:[…], none:[…] }` — flag preconditions (interactions
  are invisible to the engine until matched)
- `silent: true` — skip the auto combine-whoosh SFX for this combine
- `on: 'auto'` — fires whenever `require` is met, no user action
  needed. Re-evaluated after every fire().

### New object/zone fields (V0.16)
- `view: "junk" | "secret"` — render only when the current surface
  matches (else hidden). Used for the Ledger + handwritten-note in
  the secret-drawer view.
- `classWhen: { className: flagName }` — declarative state-driven
  CSS class. Used for the jack-o-lantern's lit-glow.

### `on:` types
- `'click'` — short press without movement
- `'drop'` — drag-release onto a zone
- `'combine'` — drag-release onto another object
- `'auto'` — sweep-fired when require flags match

### Hit-test (drag matching)
Now interaction-aware: prefers the largest-overlap target that has
a live `drop` or `combine` rule with the dragged object. Falls back
to any-overlap if no valid target is in range. Massively improves
the "objects need specific selection" frustration on a stacked
drawer.

### Author mode (`?author`)
- Drag to place
- Wheel → resize width
- Alt+wheel → rotate (objects only)
- Shift+wheel → zone height
- Surface preview buttons (4): `junk-clean`, `junk-dusty`,
  `secret-clean`, `secret-dusty`
- "Copy layout" button → pasteable JSON
- Layout cached in `localStorage` per browser

### Player-side position overrides
A drag with no matching drop target now leaves the object where the
player put it (was: snap back). Coords persist in `W.userPositions`
per puzzle version, applied at boot via `applyUserPositions()`.

## Sharp edges (carried + new)

1. **LiteSpeed cache** is still the #1 source of "did it deploy?"
   confusion. Always remind Thomas to Purge All after a push, and
   often a hard refresh (Ctrl+Shift+R) for the JS file too.
2. **Puzzle-version localStorage wipe** — bumping `version` in
   `inc/data/drawer-puzzle.json` (currently 4) wipes a player's
   progress + custom object positions. Bump only when state shape
   has materially changed (added/removed objects, renamed flags).
3. **`once: true` is permanent** — once an interaction's id is in
   `W.done`, it never fires again unless localStorage is cleared.
   Adding a new `remove:` or other action to an existing `once: true`
   interaction won't help players whose first session already
   triggered it. Bump puzzle version to force a clean re-evaluation.
4. **Hit-test prefers valid targets, but only when require/once
   are CURRENTLY satisfied.** If a future state would make an
   interaction valid, the dragged object won't be magnetised to
   that target yet. Players need to satisfy preconditions first.
5. **Modal action handlers (`choice`, `passcode`, `hangman`,
   `pacman` gameover) call `runActions` + then manually
   `save()` + `render()` + `sweepAutoInteractions()`.** This was a
   bug for two days where modal "do" lists set state but never
   persisted. Anyone adding another modal action MUST do the
   epilogue trio. Search for `sweepAutoInteractions` to find
   examples.
6. **The combine-whoosh fires BEFORE runActions.** If you don't
   want the whoosh on a particular combine (because the action
   list includes its own audio — `video:` plays the WP file's
   track, `stream:` opens a player widget), add `"silent": true`
   to the interaction.
7. **Bitcoin whitepaper PDF popup** can be blocked by aggressive
   popup blockers in rare browser configs. If a tester reports no
   PDF opening, they likely have a third-party blocker. Not
   fixable from the engine side.
8. **YouTube `iframe`s don't always stop on close** in some
   browsers — `playYoutube`'s teardown sets `iframe.src = ''` to
   force-kill audio. If a future modal-style action plays YouTube,
   it MUST do the same.
9. **Author mode position cache (`tc_drawer_author` key in
   localStorage) is independent of puzzle version.** Survives
   version bumps. Thomas keeps his author positions across re-tests.
10. **Audio file sizes** — `pacman-loop.mp3` (3 MB) and
    `arcade-bg.mp3` (3 MB) are the largest assets in the theme
    repo. They only download when the Pac-Man modal opens or the
    desk arcade is used, so visitors who never play pay nothing.
