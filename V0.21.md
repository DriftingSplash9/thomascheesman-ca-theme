## 🩹 Sharp edges discovered this session (read before touching kid-page figures)

1. **The sitewide lightbox wraps every content `<img>` in an `<a>` after load.** So inside `.heritage-line__figure`, the flex/grid items are the **anchors**, not the imgs. Target `> *` (or `> *:nth-child(n)`), NOT `img` / `img:nth-of-type(n)` — the latter silently won't match. This caused the `--rounds` mis-alignment and the `--pair` images collapsing to 2px.
2. **`loading="lazy"` won't load a zero-layout-area image.** An image that is stacked/opacity-0/absolutely-positioned, OR constrained so it has no height until it loads, hits a deadlock: lazy skips it → it never loads → it renders nothing. **Use `loading="eager"`** for such figures (the `--rounds` flipbook frames and the `--pair` images all needed it).
3. **A solid cyan/turquoise box = an `<img>` with `naturalWidth: 0` (not loaded) sitting over the cyan WebGL canvas.** When something renders as a flat colour, check `naturalWidth` FIRST. (Cost ~6 debugging rounds this session before checking it in-browser.)
4. **LiteSpeed serves cached pages** (`x-litespeed-cache: hit`). To verify a change without purging, append `?cb=<anything>` to the page URL (busts the HTML). For images cached as failed loads, append `?v=<theme version>` to the `src` (done for the sled frames). Always remind Thomas to **LiteSpeed → Purge All** after a push.
5. **Version bump = Edit tool only** (PowerShell/sed corrupt line endings — see top).
6. **Browser-inspection works:** the Claude-in-Chrome MCP (`tabs_context_mcp` → `navigate` → `javascript_tool`) drove the live site to diagnose all of the above. Very effective — reach for it instead of guessing.
