## ⭐ The voice pass — what it is and how it works (carry this forward)

Thomas writes his source answers **in tight, listed, abbreviated form to conserve energy** (chronic pain / HCS). He counts on the agent to **unfold that into his actual voice** — long sentences that breathe, em-dash asides, one concrete *real* detail, a wry self-aware turn, a willingness to wander into the little story and circle back (see `page-thomas.php` for the gold-standard cadence).

**🔑 The rule he set, in his words: "careful adding details like this ok?"** — Expand the **cadence**, never invent **facts**. He caught three fabricated details in a sample (music "under his door" → it's headphones; "wearing out" Spotify → anachronism, records predate him; "a few good years" of boxing → he boxed **one winter**). **Ground every concrete detail to his source; add nothing he didn't say.** This is the most important lesson of the session and extends the standing "verify before asserting" memory.

**The workflow that worked:**

3. Thomas edits the DOCX at his own pace.
4. Agent lays the edited prose back onto `page-{kid}.php`.

## 🩹 Sharp edges discovered this session

1. **Don't invent details — ground to source.** (See the voice-pass rule above. The #1 takeaway.)
2. **EXIF orientation is a minefield.** PIL `Image.open()`+`save()` **strips** the orientation tag → phone photos shot in portrait render sideways. Fix: `ImageOps.exif_transpose()` to bake rotation into pixels. **But some tags lie** — Facebook/Live-Photo stills (and orientation value 4) can be wrong; `exif_transpose` then mis-rotates. **Verify by eye** (the Read tool views images) using a *fixed* reference in the photo (e.g. a car's ceiling lights), not the subject's face (a kid leaning for a selfie fooled it twice).
3. **WordPress "rotate" makes `-e<digits>` copies** and leaves the original untouched — so a hardcoded URL keeps serving the unrotated file. Don't rely on WP's image editor for photos the theme references by name; bake orientation into the upload.
4. **Windows file tunneling:** delete + recreate a file with the **same name** within ~15s and Explorer **resurrects the old "Date created."** Confused Thomas into thinking nothing updated. Fix: write corrected images under a **fresh filename** (e.g. `daniel-lucas-upright.jpg`), which also dodges WP filename collisions.
5. **No WP media-upload ability** in the `thomascheesman` MCP (abilities are pages/quotes/leaderboard/create-page only; no credentials to POST `/wp/v2/media`). So: **photos can be theme-hosted** (the agent ships them via push) OR uploaded by Thomas; **videos must be uploaded by Thomas** (too big for repo). The kid pages use **WP Media for both** (consistency) — stage renamed files in `Kids-Photo-Stories\daniel-{images,videos}-for-wp\` and hand Thomas the upload list.
6. **Re-encode recipe (ffmpeg):** `-c:v libx264 -crf 23 -preset slow -pix_fmt yuv420p -c:a aac -b:a 128k -movflags +faststart` (drop to `-crf 26` + `scale ≤960` for long clips). `+faststart` is the web-optimized bit. Video playback still **can't be verified in an automated browser** — confirm in a real one.
7. **`kid-videos__grid--mixed`** (new, in style.css): flex row that stacks 2 landscape clips between 2 portrait clips so a mixed-orientation video set lines up instead of stair-stepping under the auto-fit grid.
