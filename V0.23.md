## ⭐ THE TREE SYSTEM (the rollout brief — next thread's headline)

**Model page:** the Steinke long-read. **Data:** a `tree` key on any chapter in `{line}-images.json` (Steinke's is on `"The Living Line"`). **Renderer:** `treeHTML()` in `_md2heritage.js`. **JS:** `initHeritageTreeTilt()` (pointer 3D + sheen) and `initHeritageTreeFacts()` (dossiers) in main.js — both no-op when no tree exists. **CSS:** the HERITAGE TREE block in style.css; everything tints from `--line-color` automatically.

Schema per couple: `{ "a", "b", "note" (m. place/year), "carrier" ("a"|"b" — lights the bloodline name), "children" [strings; **bold** = carrier child], "facts" [strings; **bold** = key detail] }`. Generations are rows; two couples in one row = the two parent-couples tier.

**Rollout per line (×7):** mine the manuscript's lineage table + Notes → author the `tree` block → regenerate (`node _md2heritage.js <md> <out.php> "<Label>" <json>`). Converter labels that must match existing headers: Lakeman = `"Lakeman"`, Verboom = `"Verboom"`, the rest `"The X"`. Pipeline is idempotent (verified). Privacy: living people first-names only; unnamed living relatives stay unnamed ("and two more daughters" pattern).

**Also in the rollout:** 7 blob trios re-derived in each pastel's family + 7 `body:has(.heritage-longread--{slug})` WebGL tint/accent pairs (Steinke's pair is the template). **Endgame:** the eight trees are the data spine for the one big converging tree → dovetails into Task E (`docs/CONVERGING-MAP-SPEC.md`, colours now settled in §16).

## 🩹 Sharp edges discovered this thread

1. **The pull-quote void bug (fixed 1.0.506, remember the pattern):** `initHeritagePage` animated only the FIRST `.heritage-line__quote` per section (`querySelector`, not `All`); a long-read is ONE giant section, so every later quote sat at the CSS pre-animation `opacity: 0` forever — invisible voids in the column. Watch for the same pattern in any per-section reveal.
2. **Check DOCX LastWriteTime before regenerating** — if Thomas has edited a delivered DOCX, his copy is canonical; record pending decisions in `Lay-On-Decisions.md` instead.
3. **Genealogy decoys are everywhere** — the district crawls with same-name Steinkes (a Springfield-MB "Henry Steinke b. 1904" nearly passed). Anchor on birthplace+year+household, tier every claim (VERIFIED / PROBABLE / LEAD), and never write tree-tier claims into the page as fact.
4. **PS 5.1 traps (recurring):** no heredocs (use the Bash tool with python heredocs for multi-replace edits); `Set-Content -Encoding utf8` writes a BOM that corrupts git commit subjects — use `[IO.File]::WriteAllText` for commit-message files; embedded double quotes split native-command args.
5. **WP media:** all 30 new uploads' bare stems are 200 (use bare stems, not `-scaled`). The `tc_culinary` array on page-thomas.php is the pattern for inline photo walls.
6. **The converter now renders markdown blockquotes** (`> ...`) as quote asides — they participate in the same reveal animation as pull-quotes.
7. **Editorial census drift:** the corpus is ~1,500–2,000 words tighter post-pass; V0.22's word table is pre-pass and methods differ — recount before quoting numbers.
