### G9 — CSP nonces: attempted, then **reverted** (`15fdc10`/`e7eae0e` → `c9f5b47`)
Built the full nonce machinery (per-request `tc_csp_nonce()`, `script_loader_tag` + `wp_inline_script_attributes` filters, JSON-LD nonce injection, `strict-dynamic`), shipped it Report-Only, then enforced it. **The enforced header never reached the browser.**

The multi-hour chase ended at the root cause: a **`Header always set Content-Security-Policy` block in `public_html/.htaccess`** (written by an earlier session) was stripping our PHP header and forcing the old policy onto *every* response — including static `.css`/`.js`. Disabling that block proved Hostinger's LiteSpeed injects its *own* minimal `upgrade-insecure-requests` CSP at the server layer after PHP, which also strips ours. So:
- The only header that survives is the static `.htaccess` `mod_headers` block (it runs last and wins).
- A static file can't carry a per-request nonce → **nonce CSP is structurally impossible on this host.**

**Resolution:** `c9f5b47` reverts the three files to their pre-G9 (G7) state, with one forward change — `script-src` drops `'unsafe-eval'` (audited unused). The achievable hardening now lives in the **updated `.htaccess` block** (Thomas pasted it): keeps `'unsafe-inline'` (required — inline scripts can't be nonce'd statically), drops `'unsafe-eval'`, retains `base-uri`/`form-action`/`object-src 'none'`/`frame-ancestors 'self'`/`frame-src` allowlist. The PHP header in `inc/security-and-seo.php` is kept in sync as defense-in-depth (only matters if the `.htaccess` block is ever removed), with a comment documenting the host behaviour. Verified live: hardened policy on both HTML and static, theme 1.0.592, no stray `nonce=` attrs.

**False trails ruled out along the way** (don't re-chase these): PHP opcache (Thomas toggled `opcache.enable` off/on in hPanel → no effect), LiteSpeed page cache (purged repeatedly → no effect), stale deploy (file confirmed correct on the server, version 1.0.591/592 live). It was the `.htaccess` override the whole time.

## 🩹 Sharp edges (new / reaffirmed this thread)

- **⭐ NEW — the site CSP is a static `.htaccess` block, NOT the PHP header.** Hostinger/LiteSpeed strips any `Content-Security-Policy` header WordPress sends (proven: the bare server CSP appears even on static `.css`/`.js`). The authoritative policy is `# --- TC: Content-Security-Policy override ---` in `public_html/.htaccess` (`Header always unset` + `Header always set`; mod_headers runs last). It's **server-only — not in the git repo** — so changes need Thomas in hPanel File Manager (enable "show hidden dotfiles"; there's a `.htaccess.bk` backup beside it). **Nonce / dynamic-header CSP is impossible on this host — don't re-attempt it.** Full context: [[project_tc_csp_htaccess_authoritative]].
- **CSP debugging trap:** if a CSP change "won't go live," it's almost certainly the `.htaccess` override, **not** opcache or cache. Test by curling a *static* asset's headers — if a `.css` file carries the CSP, it's coming from the server/`.htaccess` layer, not PHP. (`curl -s -D - -o /dev/null URL`).
- **Credential handling:** the Gmail App Password + `TC_SMTP_*` constants went into `wp-config.php` **by Thomas, not the agent** — keep it that way for any secret.
- **Mixed CRLF/LF** — detect per file; the Edit tool is fine for single-line, Python with NL-detect for multi-line; never `sed -i` (rewrites all endings).
- **`background-size: cover` exists at `desk-menu.css:1049`** (the mobile blurred desk backdrop) — a deliberate pre-existing exception to the no-cover rule. Left as-is; flagged so it isn't "fixed" by reflex.
- Standard: LiteSpeed purge after deploy (via the `tc-portfolio/purge-cache` ability — won't clear combined CSS/JS; Toolbox does that); **explicit `git add` paths** (tree carries `.docx`/`.xlsx`/`.mp4`/loose `build-*.py` that must never be swept in); bump `style.css` `Version:` with the **Edit tool** on every theme-code commit (docs/CI don't bump); never `object-fit/background-size: cover` (use `contain`); kid-privacy + "parents" not "co-parents"; auto-push is **TC-only**.
