## ⭐ NEXT TASK — Pinball Phase 1: PixiJS (WebGL) renderer, in place

**Goal:** big graphics jump (real bloom/glow, GPU particles, lit smooth elements) without leaving the drawer or touching the physics/logic.

**Approach (agreed):**
1. **Self-host PixiJS** like Matter — vendor a **v7 UMD build** (`pixi.min.js`, exposes global `PIXI`) into `assets/js/vendor/pixi-7.x.x.min.js`. (v8 is ESM-first / no easy UMD global — stick with v7 for the `loadScript`-global pattern.) Load it **lazily on the marble click**, alongside Matter, in `desk-drawer.js`'s `wireMarble()` (chain another `loadScript` before booting). ~140KB gz; opt-in only, so the site stays light.
2. **Replace the Canvas2D `render()`** in `desk-pinball.js` with a Pixi scene: one Pixi `Application` whose canvas replaces `.tc-pinball__canvas`. Build a `Graphics`/`Sprite` per game element **once** (walls, ramps, slingshots, drop targets, flippers, ball, the felt) and each frame **sync their `x/y/rotation` from the Matter bodies** (the `tick()` already drives everything off Matter — keep that; just update Pixi objects instead of redrawing). Keep the **HUD as HTML** (it already is).
3. **Layer on the WebGL juice** Canvas2D couldn't do well: a **bloom/glow filter** on bumpers + ball + ramps, a real **particle system** for the sparks (replace the hand-rolled `this.sparks` Canvas2D dots), smoother lit edges, a richer felt. Keep the gold-post colour ramp, the motion trail, the screen-shake, the vignette — port them to Pixi equivalents.
4. **Everything else stays:** Matter physics, the geometry (funnels/bars/gutters/slingshots/flippers), nudge, gold/jackpot, game-over panel, anti-stuck, sub-stepping, speed cap, Zelda labels.

**Verification:** you can confirm it **loads** (Pixi `Application` created, stage has children, zero console errors) via the connected browser — but **you cannot watch it render** (background-tab rAF freeze). So: build carefully, prove it initializes clean, push, and have **Thomas test the look** in a foreground tab; iterate. Expect a round or two.

**Phase 2 (later, optional):** real textured/sprite art for a fully themed table (Hyrule). Needs an art direction + assets — that's the moment to offer a **ChatGPT brainstorm** (per the drawer/BHAG workflow: ChatGPT imagines the look, Claude builds it).

## 🕹 Pinball current-state reference (read before touching it)

- **One file:** [`assets/js/desk-pinball.js`](assets/js/desk-pinball.js) (~1,350 lines). CSS: `assets/css/desk-pinball.css` (bundled). Lazy-loaded by `desk-drawer.js` on the marble click; Matter is loaded first.
- **Table:** 760×460 logical, **landscape** (it has to fit the drawer interior) — this is the root cause of the awkward outlanes; the funnels/bars/gutters all exist to compensate. The WebGL rewrite does **not** change this (still landscape, "in place").
- **Geometry now (validated in-browser by dropping balls + measuring):** funnels connect just above each flipper pivot (no corner pocket); short bouncy outlane **bars** at slingshot-top level redirect; ~22px **gutters** each side are real (occasional) outlane drains; **sloped** slingshot tops (no flat perch); flippers 104×18, pivots (270,412)/(490,412), hinge ±52; centre drain only otherwise.
- **Anti-tunnelling:** physics sub-stepped 2× per frame, ball speed capped at 24, solver iters 12/10. **Anti-stuck:** ~3s motionless → auto random nudge.
- **Features:** nudge (Left/Right Shift + B); 5 bumper "posts" warm cyan→gold over 12 hits (gold = 5× score + speed boost; all-5 = 25k jackpot + 3×); sparks; ball motion trail; screen-shake; Game Over → Play Again / Exit panel; leaderboard POST to `tc-games/v1/scores` (game="pinball").
- **Useful technique (carried):** to validate physics without playing, build a throwaway Matter world in the browser console with the same body params and drop balls, logging where each crosses the flipper line / drains / sticks. This caught the chute bug + trap pockets precisely.
