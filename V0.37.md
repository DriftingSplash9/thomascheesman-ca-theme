### 🕹 Pinball state reference (read before touching it)
- **One file:** `assets/js/desk-pinball.js` (~2,300 lines). CSS `assets/css/desk-pinball.css` (bundled). **Dual renderer**: `renderer:'canvas'` (arcade) draws via `render()`; `renderer:'pixi'` (drawer) via `buildPixiScene()`/`renderPixi()`. Shared physics/geometry/layout; the spacey theme + glow + shadows + domed posts are Pixi-only (arcade stays its wood-ish OG look).
- **Pixi v7 UMD, not v8** (v8 is ESM-first, breaks the `loadScript`-global pattern). pixi-filters 5.3.0 attaches `PIXI.filters.*`. Both load non-fatally; any Pixi failure → Canvas2D.
- Multiball: `this.balls[]`, MAX_BALLS=2, per-ball trail/anti-stuck; collisions pass the colliding ball to the handlers. Sub-steps **3**, ball speed cap **26**.
- Systems: tilt, peg on/off puzzle + outlane side-guards, score-reactive sector backgrounds, generative music + mute, top-10 scoreboard (`tc-games/v1/scores`, game="pinball" — shared by arcade + drawer).
- **⭐ Verification limit (carried):** a background/automation tab **freezes `requestAnimationFrame`/WebGL** — you can confirm it *loads clean* (Pixi app + scene, zero console errors) but **cannot watch it render**. Thomas's foreground play is the visual check. To smoke-test load: in a real browser, lazy-load the vendored libs + `desk-pinball.js?cb=…`, `TCPinball.boot(null,{renderer:'pixi'})`, check the canvas got a `webgl` context + zero errors.
