## The vision

The `/timeline` page presents Thomas's life from 1980 to 2026 as a road trip. The reader scrolls vertically; the world pans horizontally past a side-profile safari jeep pinned center-bottom of the viewport. The jeep starts full-size, and at year 2012 (the home move-in) it shrinks to 21%, slides left, and rides along the road's curves to the end. Photos of Thomas's home through the years (2012 → 2022 → 2025 → 2026) fade through as back-layer images. Per-event imagery drops onto the screen as polaroids with random rotations — a road-trip craft-album aesthetic that ties to the footer's passport metaphor. The Roll-Out sign appears at the very end.

This page is the **2D dress rehearsal for the BHAG**. The same jeep, character, and aesthetic will move to 3D inside the persistent-canvas topography when the BHAG ships. See memory `project_tc_bhag_living_document.md`.

## Architecture decisions made so far

(Cumulative — most recent first within each section.)

### Era backdrop chain (back layer)

Z-stack top-down so earlier eras fade out to reveal later ones underneath:

| Strip | z | Behavior |
|---|---|---|
| `--house-2026` | 9 | Slideshow slot, JS-driven opacity |
| `--house-2025` | 8 | Slideshow slot |
| `--house-2022` | 7 | Slideshow slot |
| `--house-2012` | 6 | Slideshow slot |
| `--foothills` | 4 | Calgary/Turner Valley/HCS, fades 0.05 → 0.13 |
| `--prairie` | 3 | Peace Country, fades 0.25 → 0.35 |
| `--forest` | 2 | Boreal forest, fades 0.42 → 0.50 (~year 2000) |
| `--night-sky` | 1 | Fades in 0.42 → 0.50, fills around home photos |

Slide centers (in `FINALE_SLIDE_POSITIONS`): `[0.70, 0.86, 0.93, 0.99]`. JS uses asymmetric trapezoidal opacity per slide so the long 2012 → 2022 gap holds longer than the tighter 2025 → 2026 transition.

The 2009 photo was dropped — Thomas didn't live in the house yet.

### Jeep handoff at year 2012

Jeep stays at full size from start until pos 0.65, then **shrinks + slides left + follows road** over progress 0.65 → 0.70 (~year 2012, the move-in era). End scale 0.21, end position `left: 10vw`.

CSS uses `--jeep-shrink: clamp(0, calc((var(--tl-prog-eased) - 0.65) * 20), 1)` plus an interpolation that mixes the fixed `bottom: 6vh` with a JS-set `--jeep-road-y` value as the shrink completes.

JS samples the road path's y at the jeep's actual visual viewport-x using a 16-iteration binary search of `roadPath.getPointAtLength()` to invert the path's arc-length parameterization. (The path's curves mean arc-length and horizontal position diverge — the linear approximation drifted ~50% of the way through the road-following stretch.) Wheel offset of -2vh from the sampled path-y empirically lands the wheels on the road's drawn line at scale 0.21.

### Prose pill below the road

Year + title + prose moved out of the jeep into a persistent `.timeline-prose-pill` styled to echo the sitewide `.tc-capsule` (frosted glass, full-pill radius). Stays visible the entire timeline so late-event prose (Settled 2025, Into the ring 2026) still narrates after the jeep shrinks.

### Polaroid drops for per-event imagery

`.timeline-polaroid` foreground container (z-index 9, above the jeep). When `crossFadeToBeat` fires and the new event has a populated `image` field, JS:
- Sets `<img>` src + caption (year)
- Generates random rotation `-8°..+8°` and random landing position `28–72vw × 26–58vh`
- Toggles `.timeline-polaroid--visible`

Initial state is `translateY(-90vh)` so the CSS transition reads as a polaroid being tossed onto the screen. Replaces on next event change. Caption uses `Caveat`/`Marker Felt`/`Brush Script` for handwritten flavor.

### Other locked decisions

- **Year locked to `events[idx].yearStart`** — discrete jumps at prose flips, no interpolation. Year and prose always align.
- **Compass locks to north (0deg)** when `easedProgress >= 0.55` — house faces south, photo POV looking north.
- **Mid layer pans leftward** like back/fore (the original carnival-duck reversal was dropped).
- **Roll-Out sign** fades in 0.99 → 1.0 over the 2026 image.
- **Page length** `--tl-length: 2000vh`.
- **Back layer** extended `right: -100vw` so it covers viewport even at maximum leftward pan.
- **Prose firing logic** uses "approach" model: prose for event[i] is active during [events[i-1].pos, events[i].pos], so the named event's marker is approaching from the right while the prose describes it.
- **Road geometry** uses 500vw element width with viewBox `-4000 0 20000 600`. Lead-in (vbx -4000 to 0) and lead-out (12000 to 16000) extend visual road past the event range. `transform: translate3d(calc(-25vw - var(--tl-pan-road) * var(--tl-prog-eased)), 0, 0)` with `--tl-pan-road: 300vw` keeps the path point at progress=P at viewport_x = 75vw at every progress value.

### 2026-04-29 evening through night (session 2) — image wiring, finale rearchitecture, jeep handoff

- The biggest pattern this session: **ship + iterate fast**. Many architecture changes were tried and rolled back within minutes when Thomas saw the staging deploy. The Hostinger auto-deploy + push cadence is fast enough that this is a real-time loop. Rough count: 4 distinct finale architectures explored before settling on the slideshow-as-back-strips + polaroids + small-jeep-on-road model.
- **Memory file `project_tc_timeline_home_finale.md` was rewritten near end of session** to reflect the current architecture (it had been describing the abandoned full-viewport video takeover). Future-Claude reading that memory will get current truth, not historical truth.
- **Binary search for path arc-length** is the trick that made road-following actually work. Linear approximation of `pPath ≈ easedProgress + (jeepCenterVw - 75)/300` drifted noticeably by ~50% along the road-following stretch because path arc-length and horizontal position diverge for curvy paths. 16 iterations of `getPointAtLength` per frame is fine on modern hardware.
- **Year-locked-to-event** was a definitive call after Thomas flagged "year and prose don't match." Tried biased interpolation first (reach target at midpoint); Thomas explicitly chose discrete locking instead.
- **Polaroid drop animation** uses `translateY(-90vh)` initial state + CSS transition for the "drop in" feel. Random rotation `-8°..+8°` and random landing position `28–72vw × 26–58vh` per appearance. Replaces on each event change; only fires when `event.image` is populated.
- **Photos kept getting moved between back layer and foreground** until Thomas's specific intent crystallized: home photos in back layer (with night sky filling around them); per-event imagery as foreground polaroids (different content category, different display style). These are now two distinct image surfaces.
- **The jeep-faces-right detail** — easy to miss. The "SAFARI" text + windshield + grille are on the right side of the image. So the front of the jeep is on the right. Headlight beam (when added) should originate at right edge.
- **Wheel offset for road-following** at scale 0.21: jeep image's wheel touchpoint sits ~2.2vh above the bottom edge of the scaled box (15% of the 14.7vh scaled height). So the JS should subtract ~2vh from the path's `fromBottomVh` to land wheels on the road's drawn stroke. Started at -3vh, dialed back to -2vh.
- **Thomas's working pattern this session continues from V0.01**: he generates assets in parallel while I scaffold; we iterate visually one tuning per push; he eyeballs staging; many corrections come back as "X is happening but it shouldn't be" or "Y is missing." Auto-deploy speed is what enables this rhythm.
