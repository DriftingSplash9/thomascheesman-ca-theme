## The vision

The `/timeline` page presents Thomas's life from 1980 to today as a road trip. The reader scrolls vertically; the world pans horizontally past a side-profile safari jeep pinned center-bottom of the viewport. The jeep starts full-size, and after the year 2014 (Township 71 closes era) shrinks to 21%, slides to the left edge, and rides along the road's curves through the family-photo era. Photos of Thomas's home through the years (2012 → 2022 → 2025 → 2026) crossfade as back-layer images. **Per-event imagery drops as polaroids** with a title at the top and an optional WP-authored description at the bottom — random rotation, random landing spot, hand-drawn caption font, persists with leftward drift, **fades out 7s after landing**. Roadside **highway signs** (AB-green, white-bordered, text + photo) sit at windshield height and pass the jeep as scroll advances. **Roll-Out** sign appears at the very end.

This page is the **2D dress rehearsal for the BHAG**. Same jeep, character, aesthetic to be rebuilt in 3D inside the persistent-canvas topography when BHAG ships. See memory `project_tc_bhag_living_document.md`.

### "If revisited" — curved lead-in correctly

If a future agent gets explicit go to retry the curve:
- Lead-in path: `M -4000 280 Q -1500 280, 0 540` (or shallower drop, e.g. y=380 start)
- **Correct** Bezier x-formula: `B_x(t) = -4000 + 5000t - 1000t²` for control point at (-1500, 280)
- Quadratic solve: `1000t² - 5000t + (targetVbx + 4000) = 0` → `t = (5000 - √(disc)) / 2000` where `disc = 25000000 - 4000(targetVbx + 4000)`
- y formula stays correct: `y(t) = 280 + 260t²`
- Apply in main.js where `targetVbx < 0` instead of binary searching the main road
- The control-point-held-near-start makes the curve "hug top, sweep down" — visually feels sudden at the end. Try a shallower start (y=380 instead of 280) for a gentler descent.

## Architecture decisions made so far

(Cumulative — most recent first within each section.)

### Polaroid system (V0.04 final state)

- **Title at top** of the polaroid, pulled from `event['title']`. Optional `event['polaroid_title']` overrides for cases where the photo doesn't match the event's narrative title (used for the "Mel, again" event's keg photo → "Relaxing after a hard day's work").
- **Image** fills the rest of the polaroid frame (object-fit:cover). Optional `event['image_rotate']` (degrees) applies CSS transform for sideways-uploaded photos with object-fit:contain.
- **Description** at bottom is pulled per-render from the WP attachment (`get_post_field('post_content', $attachment_id)` after `attachment_url_to_postid()` resolves the URL). Authored by Thomas in WP Media Library → image → Description field. Auto-updates if he edits later. Polaroids without a description don't render the strip; with one, gets `--has-description` modifier class.
- **No year** displayed on the polaroid. The capsule odometer + prose context handle the year.
- **Time-based fade** (V0.11) — `POLAROID_HOLD_MS = 7000`, `POLAROID_FADE_MS = 3000`. Polaroid lands, holds 7s at full opacity, fades over 3s. Tuneable in main.js. Decoupled from scroll position so pausing/scrolling-fast both feel smooth.
- **Drift** continues to be scroll-based (unchanged from V0.03): `--polaroid-drift = (elapsed - 0.005) × 350vw`. Polaroids slide left as scroll continues — independent of fade.
- **y-range 28..72vh** (was 12..78vh in initial V0.04 — clipped the title slot above viewport for low-y polaroids since the polaroid is ~58vh tall and centered on `--polaroid-y`).
- **Deterministic randoms** from event index — landing position + rotation are stable across reloads, different per polaroid.

### Roadside marker system (V0.04 final state)

Three marker kinds:

| Kind | Visual | Usage |
|---|---|---|
| `highway` | Green AB-highway sign, white border, "PLACE Nkm" text + 132×132 photo on right | Place markers (Turner Valley, LaGlace, Teepee Creek, Major's, Township 71) |
| `sign` (with image) | Freestanding sign sprite (transparent PNG), no chrome | Sprite is a complete sign in itself (Spirit River) — same category as Roll-Out |
| `pothole` | (parked) | HCS marker removed V0.04; was a hazard-on-road sprite |

Highway sign fields:
- `kind: 'highway'`, `label`, `text` (e.g., "Turner Valley 1km"), `image` (the photo on the sign), optional `offset` (px raised above default windshield height for staggering)

Sign + image fields:
- `kind: 'sign'`, `label`, `image` (the sprite itself)

Common positioning:
- Both highway and image-only signs are raised **30vh** above the road via CSS transform, with a long thin post bridging down to road
- Per-marker `offset` (px) adds to that — Turner Valley uses 60 to clear the Teepee Creek overlap
- Markers fade as they approach viewport center: opacity 1 at xVw > 70, fades 70→50, gone past 50. Pothole was exempt (when it existed); other markers fade.
- Markers z-index 11 (above polaroids' 9) so signs render in front during overlap

### Density-scaled lerp (V0.18)

Scroll catch-up slows in dense event clusters. `getLocalDensity(progress)` counts events within ±0.04 of current progress; `lerpFactor = 0.06 / max(1, density / 2)`.

| Density | Effective lerp |
|---|---|
| 1–2 | 0.06 (full speed) |
| 4 | 0.03 (half) |
| 8 | 0.015 (quarter) |

Eases in/out automatically as density rises and falls — no per-region tagging. Kicks in around 0.69–0.78 (OMG-baby → T71 → T71-closes → Daniel → Major's → Faith) and 0.81–0.90 (surgery / recovery / coming back).

Tuneable: `DENSITY_WINDOW` and the `Math.max(1, density / 2)` divisor in main.js.
